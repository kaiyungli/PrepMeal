# Production full Favorites RPC rollout

Ordinary full Favorites reads use the existing service-only RPC when VERCEL_ENV=production, FAVORITES_PRODUCTION_RPC_ENABLED=1, and FAVORITES_RPC_COMPARISON_ENABLED=1. The versioned deployment config enables this authorized rollout. Preview keeps its independent flag. Unknown/development environments and ID-only reads retain REST. Explicit diagnostic selectors keep their existing validation. GET caller identity always comes from requireAuth; client-supplied owner parameters are ignored. Full reads still send one database request and preserve the 24-field response mapping.

POST/DELETE, token validation, ownership/RLS, account cache, freshness, prefetch, recipe pagination, meal plans and shopping lists are unchanged. Responses for enabled full reads expose the fixed reader label and private,no-store. RPC failures return the existing fixed error and do not silently issue a REST fallback; the page's normal retry is available.

Rollback: set FAVORITES_PRODUCTION_RPC_ENABLED to "0" in vercel.json and redeploy that change, or redeploy the previous production deployment at c870690. Turning the comparison gate off also restores default REST. Do not rely on an unverified dashboard/config precedence override. Rollback does not require any database changes. Existing diagnostic RPC remains explicitly gated.

Evidence: same-build navigation samples at c870690 have REST first-read readiness 1,713/1,584ms and RPC 1,090/250ms; the two-sample averages are 1,648.5/670ms (observed 59% difference). Warm cache returns are REST18/12ms and RPC15/16ms. The file marked desktop has a 402px viewport, so it does not establish physical desktop coverage. Route/server/network warmth and viewport height differ; these observations do not guarantee a stable percentage or causally attribute all improvement to RPC/SQL. The comparison-v2 file separately contains 24 successful matching reads, but no build SHA. After its first block, total medians are REST541.5/RPC320ms while upstream read medians are almost identical (34.655/34.64ms), leaving outside-handler costs relevant.

Preflight: STABLE SECURITY INVOKER, empty search_path, client-role EXECUTE denied, service_role allowed. Hosted aggregate parity checks 3 owners/12 Favorites with zero full-projection mismatches and zero null-owner rows. No database/schema/grant/configuration changes are made for rollout.

Validation: 2,068 unit + 163 component tests, TypeScript, changed API/test lint, diff check and synthetic production-gate build. Twelve new tests cover normal verified-owner RPC/no-store, rollback gates, ID-only and REST diagnostic controls, environment isolation, fixed returned/thrown failures/no fallback and auth denial. Actual post-rollout logged-in normal Favorites operations and physical desktop timing remain to be observed; HTTP public-page/auth-wall smoke checks alone cannot establish them.
