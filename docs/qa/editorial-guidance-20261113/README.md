# Recipe editorial guidance — 2026-11-13

## Scope and review

All 303 public recipes receive two cooking tips and one meal-pairing suggestion. The 606 tips were written against each recipe's actual ingredient list and steps. Pairings use the existing catalogue and recipe roles, checking whether a staple is already present. The ten previously approved drafts retain their approved descriptions, steps, tips and pairings.

This is a desk review, **not a cooking trial**. No new cooking-time measurements or nutrition calculations are claimed. References describe the technique being consulted, not an assertion that another author's complete recipe or quantities are reproduced. Existing provenance and nutrition evidence remain intact.

The review also corrects 119 step texts across 45 recipes: missing or duplicated water allocation, instructions using unlisted ingredients, cooking completion checks, bean preparation, shellfish cooking, raw-meat handling and unsuitable generic covering instructions. Ten missing water rows and three existing water notes are included; no existing ingredient amount or nutrition field changes. One salad's method changes to `boiled` because its beans must actually be cooked. The ten approved descriptions change; other descriptions remain unchanged.

## Files

- `batch-01.json` … `batch-08.json`: per-recipe editorial drafts; the approved ten override these drafts.
- `approved-ten.json`: previously approved ten-recipe copy.
- `recipe-snapshot.json`: public recipe inputs read before editing, without internal source/nutrition ledgers.
- `targets.json`: locally generated full before/after view (not committed); tests independently reconstruct targets from the tracked snapshot and patch.
- `payload.json`: exact bounded content changes and expected database hashes.
- `references.json`: consulted primary cooking and food-safety sources.
- `catalogue-query.sql`, `database-preconditions.json`: deterministic ID-ordered, numeric-scale-normalized input checks. These checks retain actual numeric values.
- `protected-baseline.json`: hashes of protected recipe fields, existing metadata and non-water ingredient rows; no private metadata is exported.
- `apply.sql`, `rollback.sql`: guarded single transactions, generated by the scripts below.

To regenerate, run `python scripts/buildEditorialGuidanceReview.py` followed by `python scripts/renderEditorialGuidanceSql.py`. Regeneration does not connect to or modify the database.

## Application boundary

The mapper reads only versioned `source_data.editorial_guidance` matching the current recipe fingerprint. A changed ingredient, step or role invalidates the reviewed copy and uses the existing fallback. The API returns only reader-facing tips, pairings and HTTPS references, never the source ledger or editorial audit metadata. Standalone SSR and the existing modal use the same shared detail component. Layout, shopping calculations and planner logic are unchanged.

The content transaction checks all 303 originals before changing anything, locks target rows, refuses existing editorial metadata, permits only water additions/notes, and checks every protected recipe field before commit. Rollback refuses changed reviewed content rather than overwriting subsequent edits. Run rollback only for this specific batch, after inspecting current state.
